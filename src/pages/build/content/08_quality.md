Quality assurance on this project adapted Hardman's AI Evals framework to an L&D context. When the practitioner's core job shifts from authoring content to evaluating AI-generated content, the critical skills become specification, which defines "good" precisely enough for AI to produce it, and verification, which reliably detects when output fails that bar. The method is a binary pass/fail cycle: select an output type, collect samples, define checks, score, diagnose root cause (specification failure vs. generalization failure), revise the specification, re-score, and repeat on a schedule.

Applied across four output categories and six data files, it ran as ten structured verification passes, a triple-validation protocol for the data files, and an eight-check capability framework, all recorded below. Everything the passes surfaced was resolved before or during the build.

## The single-evaluator limit

The structured passes above were run by the same person who authored the content, so specification failures are hardest to detect where the specifier and the evaluator share a mental model. An independent review of both the code and the content by a different model, Claude Fable, provided a second pass that did not share that mental model and surfaced issues that were then fixed. The same conflict was named in the capstone pilot, where the instructor was also the researcher ([Ritchot, 2025](https://ritchot.me/docs/capstone.pdf), p. 39). Its controls included success criteria fixed in advance, critical feedback kept in the analysis, anonymous labeling of responses, and triangulation across four data sources (pp. 39–40). The pass/fail checks above carry the first two forward. The independent model review stands in for the third, though it does not replace what an organizational deployment should add: an evaluation role separate from authoring, with inter-rater reliability established for the check framework. Still, the work had more than one reviewer, and the binary pass/fail format is designed to transfer: its checks are specific enough that a different evaluator would reach substantially similar conclusions. That transferability is the practical test of whether the methodology scales beyond one person.
