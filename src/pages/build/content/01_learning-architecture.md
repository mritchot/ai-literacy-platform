This is the learning architecture behind *AI Literacy for the Modern Workforce*: four modules on a Context → Evidence → Mechanism → Application arc, each mapped to the 4D competencies, the practice activities that build them, the performance objectives they satisfy, and the assessment tier that measures each one. The whole structure was designed to feed a [Kirkpatrick evaluation](#/evaluation): every objective resolves to a tier, and two objectives produce artifacts the [30/60/90-day behavioral follow-up](#/evaluation/level-3-behavior) can track.

The program was scoped for two delivery platforms in parallel: a custom-coded React environment (Component 4, the platform you are reading this on) and an Articulate Rise/Storyline build (Component 5). The custom platform shipped. The Articulate build was deferred as a budget decision, not a design one, and the [resource plan](#/build/resources) gives the rationale. The architecture keeps both columns so the instructional design stays platform-agnostic: only the interactive components are platform-dependent, and the content could be rebuilt in any equivalent authoring tool from the same objectives and activities.

Module 3 also inherits four design principles from the capstone pilot that preceded this build{{cite:ritchot-2025#design-principles}}. Scaffold abstract content from concrete analogies upward. Visualize the invisible with diagrams and tokenizer demos. Embed reflection and scenario-based application. Chunk content, with feedback after each part. Three Module 3 components answer that pilot's specific findings. The tokenizer playground (P5) is the pilot's first recommendation and answers its participants' request for a tokenizer sandbox{{cite:ritchot-2025#tokenizer-sandbox-37-41-43}}. The number-tokenization comparison in §3.2 descends from one of the two visuals participants named as making the content concrete{{cite:ritchot-2025#concrete-visuals-43}}. The playground's free mode shows the token count and compression ratio for any text, so learners can test the first half of the pilot's cheat-sheet rule, clean input means fewer tokens and better output, which every pilot participant applied in the scenario task{{cite:ritchot-2025#cheat-sheet-38-41}}.
